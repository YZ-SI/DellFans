# 验证

本页包含两部分：[传感器读数验证方法](#传感器读数验证方法)，以及在一台 Dell 小主机上得到的[真机验证结果](#真机验证结果010)。

## 真机验证结果（0.1.0）

机器：一台 Dell 小主机（13 代 Intel Core，6 P + 8 E，20 个逻辑处理器），Windows 10 x64。
只记录已在这台机器上实测通过的项目，测量值为实际读数。

### 1. 绿色包启动

| 项 | 结果 |
|---|---|
| 双击 `DellFans.exe` | 从解压目录启动；请求管理员权限后启动同目录的 `DellFans.Service.exe --portable`（普通后台进程，未注册任何服务），并启动托盘；窗口随即连上并显示读数。 |
| 数据目录 | 控速程序创建并保护 `%ProgramData%\DellFans`：属主 Administrators，仅 SYSTEM 与 Administrators 可写。 |
| 首次检测 | 只读检查全部通过（WMI 类与令牌、SMM 转速、BIOS 风扇模式、CPU 温度来源、硬盘温度）；打开窗口弹出“检测风扇控制接口？”，同意后全速响应测试转速 1375 → 5454 RPM，读回确认已交回 BIOS 自动，随后开始接管。 |
| 托盘“退出 DellFans” | 控速程序交回 BIOS 自动（`FanCtrlOvrd` = Disabled）后退出，托盘随之退出。 |
| 主界面 | 重复启动只聚焦已有窗口；关闭窗口后进程退出，托盘与控速程序继续运行。 |

### 2. PawnIO 驱动

| 项 | 结果 |
|---|---|
| 同意后安装 | 同意 → UAC → 下载固定版本 → SHA-256 与签名者校验 → 静默安装 → 界面报告结果。 |
| 驱动包损坏 | 系统里残留的驱动包缺少 `PawnIO.sys` 时，安装后确认驱动能打开，否则报告失败并给出修复命令；修复后驱动正常。 |
| 温度来源 | `SensorSource = PawnIO IntelMSR`，14 个物理核（6 P + 8 E）。 |

### 3. 传感器准确性与实时性

`DellFans.Cli.exe --verify-sensors --seconds 120 --load 30`，参照 HWiNFO 共享内存：

| 项 | 判据 | 结果 |
|---|---|---|
| CPU 封装温度 vs HWiNFO | 差的中位数 ≤ 1 °C | 1.0 °C（n = 480） |
| 核心平均温度 vs HWiNFO | — | 中位差 0.44 °C，p95 1.9 °C |
| 控速程序数据年龄 | p95 ≤ 1.5 s | 中位 0.50 s，p95 1.19 s |
| 传感器 → 控速程序快照 | — | 中位 0.11 s，p95 0.25 s |
| 不变式（核心最高 = 各核最大，平均 = 均值，封装与核心最高差 ≤ 6 °C） | 0 违反 | 0 / 1440 |
| 过期事件 | 0 | 0 |
| 风扇转速 SMM vs BFn（BIOS 自动时） | 差的中位数 ≤ 200 RPM | 0 RPM（n = 40，两个接口读数一致） |

### 4. 模式

| 项 | 结果 |
|---|---|
| 升速 | 高于起调温度时目标实测每秒 +52 RPM（规格 +50）。 |
| 降速 | 低于起调温度 − 3 °C 稳定 20 s 后开始，实测每秒 −102 RPM（规格 −100）。 |
| 静音上限 | 满载时目标停在 3000 RPM。 |
| 模式切换 | 温度低于新模式起调温度 − 3 °C 时直接从新模式最低转速开始（静音／平衡／高性能互切均验证）。 |
| 全核满载 | 控制线程不掉控：121 / 121 个采样处于接管状态。 |
| 切换入口 | 主界面与 CLI `--mode` 切换立即生效。 |

### 5. 恢复路径

| 场景 | 结果 |
|---|---|
| 接管中强杀控速程序 | 监护进程执行 `--recover`，风扇交回 BIOS 自动；托盘发现控速程序退出后请求重新启动，新控速程序约 10 s 后恢复接管。 |
| 接管中强杀监护 | 控制循环在下一轮（≤ 120 ms）发现监护退出并停止写转速；交回 BIOS 属性 `FanCtrlOvrd` 经 WMI 约 9 s（读一次约 2 s，先读、写、再读确认），期间风扇保持原转速，之后按 BIOS 自动回落；约 24 s 启动新监护，27 s 恢复接管。无监护时不写固件。 |

### 6. 权限与安全

| 项 | 结果 |
|---|---|
| 非提升（非管理员）令牌 | `--snapshot` 成功（客户端确认对端是同目录下已提升的控速程序）；`--test-fan`（满速响应测试）被拒，exit 1。 |
| 远程连接 | 经 SMB 回环 `\\127.0.0.1\pipe\DellFans.Control.v2` 和计算机名路径连接均被拒（Access denied），本机 `.` 路径正常。 |

### 7. 资源占用

绿色包，接管中，60 s 采样：

| 项 | 结果 |
|---|---|
| 常驻私有内存 | 控速程序 28.4 + 托盘 1.4 + 监护 0.5 = 30.3 MiB（目标 < 70 MiB） |
| 主界面 | 打开时 31.3 MiB；关闭窗口后进程退出 |
| CPU | 三进程平均 0.05 %（100 % = 全部 20 个逻辑处理器）；远低于资源保护阈值 3 % |

## 传感器读数验证方法

目标：证明风扇转速、CPU 封装温度、核心温度是**实时**且**准确**的。

### 方法

| 层次 | 做法 |
|---|---|
| 解码正确 | MSR 按 Intel SDM 公式（TjMax = `0x1A2` 位 23:16；温度 = TjMax − `0x19C`/`0x1B1` 位 22:16，位 31 有效）做表驱动单元测试；自洽检查：核心最大 = 各**物理核**最大，核心平均 = 各物理核平均（0x19C 是每物理核一份，超线程同胞读数相同，不重复计入；混合架构按 P/E 核命名，例如 6 P + 8 E = 14 核 / 20 逻辑核时行名为 `P-core 0..5`、`E-core 6..13`，与 HWiNFO 一致），封装与核心最大相差几度以内 |
| 准确 | 同一时刻与独立实现比对：HWiNFO64（自带驱动，独立读同一片内 DTS，期望 ≤ 1 °C）；ESIF（Intel 平台固件，路径完全不同，期望平均 ≤ 2 °C）；风扇：SMM 与 BFn 两条 Dell 固件接口互比 |
| 实时 | 每个读数带采集时刻；记录 传感器→控速程序→管道→界面 每跳延迟并设上限；数据源停更时标记 Stale 并退出控制 |

### `DellFans.Cli.exe --verify-sensors`（只读）

```
DellFans.Cli.exe --verify-sensors [--seconds 120] [--load 30] [--output <目录>]
```

- 本进程内起一份传感器层，每 **250 ms** 取一次；同时每秒向控速程序要一次 `Status`（`Detail:true`，控速程序没有应答时报告 `service: not found`）。
- `--load N`：从第 `min(10, 秒数/4)` 秒起对全部逻辑核加 N 秒负载（BelowNormal 优先级；封装/最高读数 ≥ 85 °C 时立即撤销）。不带 `--load` 完全不产生负载。
- 若存在 HWiNFO 共享内存 `Global\HWiNFO_SENS_SM2`（需在 `HWiNFO64.INI` 的 `[Settings]` 加 `SensorsSM=1`，只读），加入与 HWiNFO 的差值。
- 风扇 SMM 与 BFn 互比**只在控速程序已应答且没有接管风扇时**进行；接管时写 `skipped: service owns firmware`，控速程序没有应答时一律不碰固件。
- 输出目录里的 `report.json`（逐项结果、每个来源的刷新间隔、差值统计、逐跳延迟、不变量、过期事件）和 `samples.csv`（每 250 ms 一行；控速程序样本与风扇样本各占一行），并在控制台给出 PASS/WARN/SKIP 摘要。

| 项 | 判据（超出即 WARN） |
|---|---|
| 与 HWiNFO | 封装温度差的中位数 ≤ 1 °C |
| 与 ESIF | 封装温度差的平均 ≤ 2 °C（传感器层本身用 ESIF 时跳过） |
| 控速程序数据年龄 | p95 ≤ 1.5 s（行采集时刻到客户端收到） |
| 控速程序与直读 | 封装温度差平均 ≤ 2 °C |
| 不变量 | 核心最大 = 各核最大、平均 = 平均值（容差 0.15 °C，行已取整到 0.1）、封装与核心最大相差 ≤ 6 °C |
| 过期事件 | 0 次 |
| 风扇 SMM vs BFn | 差的中位数 ≤ 200 RPM |

纯分析部分（`src/SensorVerificationAnalysis.cs`）有离线夹具测试：`tests/run-verify.ps1`。
